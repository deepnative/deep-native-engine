## Next vertical outcome: FND-002 practice saved to the member account

Under #34, integrate one complete FND-002 journey in all three example variants: **worked source → attempt → specific correction → fresh case → first/revised request and reason → explicit save → return to that exact record**. This is the first integration step, not a replacement for the six-lesson, capstone, feedback and contribution requirements mapped above.

Reuse the catalog, member session and historical reading-activity contracts. Add a typed instructional payload and private practice record with explicit schema/content/variant/source identity. Keep first request, revision and reason independently addressable; include question/choice and current step only where they affect resume. Record revisions with optimistic conflict checks and a retry identity; server confirmation controls whether a save is reported as successful. Supply exact record export and integrate the existing account/workspace deletion path. Storage/schema design must preserve existing one-note practice and submitted assignment semantics.

For this first journey, each of the three writing fields permits up to **30,000 UTF-16 code units**, matching the local field convention; the three-field aggregate is at most **90,000 code units**. The dedicated save endpoint must enforce a **1 MiB maximum encoded request body**, bounded identifier/choice fields and rejection of unexpected fields. Test Unicode and percent-encoded form bytes, not just ASCII character counts. Main currently defaults to a [16 KB form limit](https://github.com/deepnative/deep-native-engine/blob/c367abbc8bdb93c1005e6278bf333e3e172712d4/src/app.ts#L475); extend only the new endpoint, leaving unrelated limits intact. Validation failure or HTTP 413 must leave the member's in-page words editable/copyable/downloadable rather than navigating away and losing them. The later six-field capstone requires its own explicit aggregate/transport contract and checks; this three-field limit does not silently constrain it.

The persisted identity and conflict boundary must include the instructional variant, not just store it as descriptive metadata: Everyday and Work writing for the same FND-002 version must coexist without overwrite. Recheck authorization after waits/locks before committing a save or returning a private export, including session expiry as well as revocation/deletion.

No automatic migration of browser-local notebooks is included: keep the existing preview, old bytes and downloads intact. A later import must separately prove source matching, limits, preview/confirmation and failure recovery. This avoids pretending that one course-wide browser content hash is the application's member/content/version identity.
