# CTP-020 local circle preview

This slice lets an active local preview member opt into one of three synthetic learning topics, see aggregate remaining seats, and leave. Topic descriptions and four-seat capacities live in `assets/docs/content/circles/preview-circles.json`; private, mutable membership lives in PostgreSQL migration 014. Nothing posts to a community, books a clinic, records attendance, shares a member name or evidence, or grants paid service.

The circle table is separate from `cohort_memberships`. A join cannot authorize shared cohort content or private evidence. Reads derive the member from the active hashed browser token and return only the caller's joined state plus aggregate counts. Writes require the existing same-origin and CSRF checks. A transaction-scoped PostgreSQL advisory lock for each topic serializes capacity checks and last-seat joins. Repeating a join is idempotent; leaving ends the active membership, and rejoining uses the same row. Only active, unrevoked members occupy seats; an expired preview releases its seat without making the historical row visible. Deleting the local preview cascades its memberships. An expired or revoked token cannot list, join or leave.

The topic JSON is Git-versioned and its fixed IDs, goals and capacities are validated by the repository gate. Migration 014 adds one isolated table and can be rolled back only after checking that no preview memberships need preserving: `DROP TABLE preview_circle_memberships; DELETE FROM schema_migrations WHERE version=14;` in a controlled database transaction. The runtime still supports only loopback demo/test mode; this design does not establish hosted identity, moderation policy or retention operations.

The approved local scenario register `initial-learning-v17` maps L44–L46 to cross-audience opt-in, the last-seat race and cohort isolation, and leave/session revocation. Unit tests cover server states and SQL branches; real PostgreSQL tests cover concurrent joins, idempotent leave/rejoin, expired credentials, cohort denial and deletion cascade. The full ECO-04 journey remains outstanding until participation rules, authorized moderation/reporting and hosted privacy controls are approved and implemented. Expert clinics, payment and recording are separate future decisions.

The later `initial-learning-v66` register adds critical L96 for a leave request held behind a PostgreSQL membership-row lock until its owner session expires. A fail-first real database race on `edecb56` returned success and set `left_at` after expiry because the original single statement used its start-time `CURRENT_TIMESTAMP`. The repaired leave locks the current principal, then a nondeleting workspace, then updates the owned membership and checks PostgreSQL wall time before committing. Late expiry rolls the write back; a revoked principal or already deleting workspace cannot initiate a leave. A second fail-first race showed that a transaction starting before a concurrent leave/rejoin could set `left_at` earlier than the new `joined_at` and violate the membership constraint; the write now uses the actual database wall time. A failed database transaction does not claim success. The lock order keeps this privacy write compatible with the existing upload and deletion paths. The real database tests also cover principal-row waits, valid/repeated leave, a rejoin ahead of the waiting leave, and unchanged rows after denial; L96 checks the actual error page and unchanged membership on desktop and mobile. These remain synthetic local-preview checks, not approved hosted cohort privacy.

Rollback of this authorization change must retain the late-expiry regression and member data. If an operational failure appears, stop the local preview, inspect the affected membership and session state, and make a reviewed forward repair; restoring the original single-statement leave would reintroduce the reproduced post-expiry write.
