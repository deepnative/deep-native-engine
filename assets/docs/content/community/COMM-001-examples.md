# Bounded peer replies and contribution draft

These are **simulated** examples. A peer can ask a useful question or point to evidence; only an assigned qualified reviewer can publish formal rubric assessment. A circle membership or reply never makes private assignment evidence public.

## Three learner questions and peer responses

**General learner question:** “My invented community-event plan assigns one volunteer to three tasks at the same time. How can I fix it?”

**Peer response:** “The two-hour limit and 12 volunteers are the facts you supplied. Put tasks on a timeline, then check that no person has overlapping roles. I have not seen the group's real availability, so ask the organizer before using the plan.” This offers a check without an expert grade.

**Non-IT professional question:** “The action table gives Alex a due date that was not in the synthetic meeting notes. Should I leave it?”

**Peer response:** “Mark the date unknown and ask the team to agree it. Keep Alex as feedback owner only because the note supports that. I am responding to the sample, not approving the team's actual work.”

**IT practitioner question:** “My sign-up test list covers success but no privacy case. What should I add?”

**Peer response:** “Compare the user-visible response for new and existing synthetic email addresses, and record what you observe when you actually run the tests. The requirement says the page must not expose account existence. I have not run your tests or formally reviewed the implementation.”

## Attributed contribution draft

**Proposed title:** “Unknown is a useful field in an action list.” **Proposed contributor attribution:** “Sample Contributor A (fictional training identity).” **Rights statement:** the text below is an original synthetic example written for this repository; there is no real contributor whose name or permission can be inferred. **Requested destination:** a future learning-circle resource draft only; no public publication approved. **Version:** 1. **Editor state:** awaiting review. **Member consent state:** illustrative only, not a recorded real consent.

> When a note does not name an owner or date, put “unknown” in that cell. Add a short question for the team. A clear unknown is more useful than a confident invention. Before sharing an action list, compare every owner and date with the original note.

**Draft editorial check:** The idea matches the synthetic meeting example; the claim is narrow and noncredentialed. Before an actual member contribution could be published, an authorized editor must confirm the member's real authorship/rights, chosen audience, privacy, source accuracy and version, then record approval. A rejection leaves the draft unpublished. A later sharing revocation removes the approved view according to the disclosed policy without rewriting the historical review record.

## Moderation and visibility exercise

If a peer reply includes a real client's name or insults another member, do not quote it into the lesson. A future member should be able to report it; an authorized moderator would review the smallest necessary context and apply the community policy. The current local app has no general circle discussion or moderation interface. This paragraph is a design example, not proof that those operations exist.
