# CTP-012: private synthetic slot holds

Issue [#296](https://github.com/deepnative/deep-native-engine/issues/296) adds an **internal-only** operation that claims one explicit sample slot and reserves exactly 60 manually seeded synthetic minutes in one PostgreSQL statement/transaction. Coaching requires `coach_minutes`; formal review requires `review_minutes`. The operation has no HTTP route, member booking control, payment, provider call or automatic grant. A returned hold ID is not a confirmed appointment or qualified-service promise.

Migration 028 stores only synthetic member, slot, grant and reservation IDs, state and UTC timestamps. A partial unique index permits one `held` row per slot. The hold function serializes an idempotency key, locks the slot and verified primary/backup roster rows, checks active future capacity and member-owned matching grant, then locks that grant before updating its conserved balance, reservation, hold and immutable event. A PostgreSQL exception rolls back all four writes. This lock order is also used by explicit expiry: idempotency key, slot, hold/reservation/grant. Generic ledger settlement refuses a reservation attached to a slot hold, so it cannot release the minutes while the slot remains held.

The internal caller supplies an explicit deadline after the current instant and no later than slot start. There is no default duration or approved 24-hour cancellation rule. Expiry is explicit, not scheduled by this slice: a caller must invoke it after the deadline before an expired held slot can be reused. Expiry changes the hold and reservation state and writes one immutable release event in the same transaction. Reserved minutes return to `available` only if the grant and member remain current; otherwise they move to `expired`. A repeated identical key returns the original result; a changed payload conflicts. No silent credit minting or category substitution occurs.

The preview page remains read-only and nonbookable. It hides a slot while an internal hold is active and can show it again after explicit expiry, if roster and capacity still qualify. There is no live roster, member-facing booking workflow, approved service term, cancellation/no-show/provider-credit policy, staffed rescheduling, or background expiry worker. Those remain on [parent #29](https://github.com/deepnative/deep-native-engine/issues/29) and its decision dependencies. The existing manually seeded synthetic ledger is not an approved member entitlement. The full-MVP browser denominator remains outstanding; no internal-only operation is counted as a new member journey.

For rollback, stop internal hold calls and preserve/export any non-synthetic hold and immutable event history before a reviewed schema removal. Dropping the table or its referenced slot/grant rows would erase linkage. Member deletion cascades the synthetic rows under the existing local-preview retention policy; ordinary event mutation remains blocked. Do not run this hold path with real service data until a qualified roster, policy, access, retention and expiry-operation review is complete.
