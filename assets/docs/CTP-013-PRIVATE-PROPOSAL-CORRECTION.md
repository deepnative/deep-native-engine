# Private proposal correction (#351)

This local, synthetic feature lets an active member correct the title, sample body and source note of an existing private **draft** while retaining its proposal ID. It does not submit the draft. Generic drafts and proposals pinned to an eligible current synthetic workflow version can be corrected; a stale or retired workflow draft stays owner-readable and withdrawable, without silently changing its reference. The moderation queue continues to show only submitted or quarantined proposals, and the public workflow library never reads private proposal text.

Every proposal has a positive revision beginning at 1. A successful correction replaces the three current text fields and advances the revision once; earlier draft text is not retained as a new history. The editor and submission form carry the revision shown to the member. A stale edit or submit returns a conflict without overwriting text or sending a revision the member did not confirm. Submission still requires the separate original-rights declaration. A submitted, quarantined, rejected or withdrawn item cannot be edited, and a waiting correction cannot undo withdrawal or account deletion.

The server derives owner, workflow ID/version and state from the stored row. It rejects malformed or duplicate form fields, invalid text, forged immutable fields, missing Origin and bad CSRF. Member principal and workspace eligibility are checked within the database transaction before locking the proposal. A concurrent session revocation or deletion marker either wins before the correction and denies it, or waits for that correction's commit. Transaction errors before commit roll back without a partial revision or state change. If the response after a commit is uncertain, the page says so and the member must inspect the current draft before retrying. Another member and staff-only credentials cannot read or change it.

The bounded owner-only structured export includes the **current** permitted proposal text and revision in `local-member-records-v7`. Withdrawal retains a redacted row with null private text; deletion removes it. Export is a synthetic current-state snapshot, not a hosted portability or backup-erasure promise. The revision does not add a right to publish, a license, a qualified reviewer decision, prior-text retention, or a paid entitlement. Parent [#115](https://github.com/deepnative/deep-native-engine/issues/115), privacy [#40](https://github.com/deepnative/deep-native-engine/issues/40), and rights gate [#97](https://github.com/deepnative/deep-native-engine/issues/97) remain open.

Migration 041 adds the revision column with 1 for existing proposals, preserving their current state and text. Rolling back to an older binary is not consent-safe because its submission path does not compare the member's displayed revision. Disable both correction and submission routes during rollback until a revision-guarded binary is restored; retain the additive column and existing private rows. Do not drop member records or claim live retention resolution as a rollback shortcut.
