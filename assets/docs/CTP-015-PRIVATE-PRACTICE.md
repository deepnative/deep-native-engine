# CTP-015 private sample practice (#198)

This local slice adds a separate, explicitly saved note beside the ephemeral study reflection (#182). A signed-in member sees a goal-specific prompt only for the latest published lesson version that matches their current goal, background, domain, experience and prerequisite. A pending qualified-signoff flag denies the source. The page cites the version, shows the synthetic source and states that the comparison is locally simulated, unreviewed and insufficient to assess competence. There is no provider call, paid allowance or career-path requirement.

Migration 021 adds `private_practice` with a composite member/content/version key, a foreign key to the exact source, a 1,000-character bound and `ON DELETE CASCADE` through `learners`. Session-derived membership is the only read/write selector; the browser cannot supply a member ID. The first save for a version wins, exact replay is idempotent, and a different later response conflicts. A transaction locks the eligible source and member for the save. The current page never retargets an old note to a replacement version. History can display the member's original words for an unavailable source but cannot issue fresh comparison feedback. Account deletion removes the row.

The response is private, mutable user data in PostgreSQL. Public authored curriculum remains a separate Git-versioned-file direction; this migration does not move it. Rollback before any member data exists can drop `private_practice` and remove schema version 21. After data exists, the safe operational rollback is to disable the practice route while preserving the table and private history until an explicit retention/deletion decision; dropping it would erase member notes. No live deployment or qualified source acceptance is implied.

Verification is mapped to [L58](../../tests/e2e/scenarios.json) on desktop/mobile Chromium, unit route/store tests and the real PostgreSQL isolation/concurrency/cascade test. The full-MVP 100-case register remains outstanding.

## One-note withdrawal (#353)

The later [#353 child](https://github.com/deepnative/deep-native-engine/issues/353) lets an active owner withdraw one retained note by its exact lesson ID and version, including after the lesson is replaced or retired. The row remains as a text-free marker with a withdrawal time so an old first-save form cannot recreate the response. A repeated withdrawal leaves that marker intact. Other versions and other members' notes are unaffected. The member's history shows the withdrawn state without response or simulated comparison; it does not make an old source eligible again.

Migration 042 changes the response column to nullable and adds the withdrawal marker, with a constraint that a saved row has text and no withdrawal time while a withdrawn row has no text and a withdrawal time. Save and withdrawal coordinate through the current principal and member workspace before taking the source or practice-row lock. The member's final session expiry is checked before commit. A failed or uncertain write must not be presented as a confirmed withdrawal; the member is directed to reload private history. The owner-only structured export v8 includes the withdrawn state and time with `response: null`, subject to its existing record and byte limits. Account deletion still removes the marker through the existing cascade.

Rollback after a withdrawal cannot safely restore its erased words. Keep the additive schema and marker rows. An older practice binary must not be exposed for saving, because it cannot distinguish a withdrawn slot from an empty one; disable practice writes until a withdrawal-aware binary is restored. An older export binary must likewise stay disabled if it would omit the disclosed marker. This is local synthetic redaction only; it does not promise hosted backup erasure, legal retention approval, public sharing or qualified feedback. [L81](../../tests/e2e/scenarios.json) is the desktop/mobile acceptance journey for this child; broader #34 and #40 criteria remain open.
