# CTP-016: local synthetic manual observation register

This is the bounded local-preview slice of [CTP-016 #32](https://github.com/deepnative/deep-native-engine/issues/32), delivered under [child #313](https://github.com/deepnative/deep-native-engine/issues/313). It records an **invented, unverified manual observation** for an existing synthetic member. It does not receive money, verify a provider event, issue an invoice, confer a paid entitlement, consume or grant service units, approve an offer, or deliver a service.

In test/demo mode an active `platform_admin` can visit `/operator/test-receipts`, enter the local member ID, a `SYN-` reference and integer CAD cents, and confirm that the record is invented. The server sets the actor, timestamp and fixed `unverified_manual` status. The form supplies a unique request key; an identical retry returns the first record, and the same key with different details conflicts. No member background, goal, or historical coaching-price hypothesis changes this rule. Members, other staff, anonymous, expired and revoked sessions cannot see or write the register. Live mode is unavailable; the current runtime also refuses live hosting.

The table is append-only while a member exists. Local member deletion cascades its synthetic observations; a removed staff principal does not erase the actor ID from surviving records. The register keeps only member and actor IDs, amount, invented reference, key, state and timestamp. It stores no card, bank, provider payload or raw receipt. It does not write the entitlement ledger or customer-facing views. The newest 100 observations are shown on the internal page; this is a bounded preview, not an accounting export.

The approved [L72 browser journey](../../tests/e2e/scenarios.json) exercises desktop and mobile for IT, other-profession and general learners. Unit and PostgreSQL integration tests cover parsing, authorization, idempotency, concurrency, immutability, rollback and deletion. The full-MVP payment path remains outstanding in #32 until provider contract/signature verification, invoice and service-state rules, approved commercial terms, tax and retention decisions are independently evidenced. No external payment provider is configured or contacted by this slice.
