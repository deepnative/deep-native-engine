# Private lesson usefulness input (#307)

The local preview asks a member who has self-assessed one current curated synthetic lesson version whether it helped them choose a practical next step. “Helpful” and “not helpful yet” are self-reports. They are neither observed skill nor a qualified review. The response is never sent to a model, published or retained after member deletion. The synthetic operator endpoint now uses only a [suppressed, coarse aggregate](CTP-022-LOCAL-METRICS.md), not a raw member answer or a reviewed learning outcome. The three audience paths use the same action; no background, goal, career path or purchase changes eligibility.

Migration 031 stores one answer per member/content ID/version, two allowed choices, a positive optimistic revision and reported/updated timestamps. The row is bound to `lesson_activity` and cascades with account deletion. A first answer uses insert-on-conflict denial; a correction updates only when the submitted revision still matches. Concurrent stale corrections cannot overwrite the winner. Only an active member with self-assessed activity on a current published curated version can answer or correct. Withdrawal requires the current owner and revision, including when a version later becomes historical. Staff, other members, retired/superseded versions, unsigned qualified content and forged versions are denied. Session and CSRF/Origin checks also gate the HTTP route. A failed write shows no success and asks the member to reload the private activity page.

The bounded member export is now version `local-member-records-v6` and includes only the owner's retained answers. The existing 100-record and 256-KiB limits still fail closed. Local deletion reconciliation includes the new row. Rollback in a controlled local database requires first handling any reports that must be preserved under an approved policy, then dropping `lesson_usefulness` and deleting schema migration 31 in a transaction before running older code. This is a forward schema migration in normal operation. It provides no hosted backup/WAL erasure or legal retention decision.

The separate parent #121 still needs defined enrollment/withdrawal cohorts, safe overlapping segments, an approved operator usefulness metric, a decision on post-deletion event retention, and accepted full-MVP evidence. The recommended default remains no retained deleted-member analytics. No live analytics or launch readiness is established by this synthetic feature.
