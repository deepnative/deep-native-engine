# CTP-012: local slot-discovery slice

Issue [#294](https://github.com/deepnative/deep-native-engine/issues/294) adds a private, read-only preview of explicit 60-minute appointment windows. A coverage interval in `expert_registry` is never itself shown as an appointment. The new `expert_availability_slots` table stores an exact UTC window, source registry row, operator author and version; retirement preserves the row and increments its version. The internal store permits creation/retirement only for a current operator or platform administrator. It serializes writes for both primary and backup staff and rejects an unverified, retired, outside-window, overlapping or capacity-insufficient record. Active future sample slots consume their primary and backup preview-minute budgets, so separate windows cannot exceed the remaining verified minutes. There is no staff-facing authoring route in this slice.

The member page requires an active session and shows only domain, service type, local time with numeric UTC offset, and exact UTC start/end. A member without a valid saved IANA zone receives a profile action rather than a misleading local time. The page has no booking, payment or reservation endpoint. Its response hides staff IDs, costs and qualification documents, catches database failures without exposing details, and never asserts a booking or live qualified service. The running app remains loopback demo/test only. Synthetic roster/slots in automated tests are labelled as samples; no real expert roster or approved offer is installed.

The one-hour window is a preview fixture for the historical 45-minute coaching call plus 15-minute preparation invariant, not approved commercial terms. Formal-review duration and staffed rescheduling are still undecided. Parent [#29](https://github.com/deepnative/deep-native-engine/issues/29) retains booking plus atomic ledger/capacity reservations, cancellation, no-show, provider replacement credits, and DST/policy acceptance. A real slot cannot be published until qualified roster and capacity decisions in #13/#96; paid booking also depends on #27/#95. Shared foundation access does not depend on these services.

For rollback, stop slot writes, remove the page/store wiring, and retain or export any non-synthetic slot history before dropping migration 027's table in a reviewed data migration. Do not silently discard a future real operator's availability history. The migration only adds a table and index, leaving existing member/ledger state unchanged. No member profile, booking, payment or provider telemetry is stored in slot rows.
