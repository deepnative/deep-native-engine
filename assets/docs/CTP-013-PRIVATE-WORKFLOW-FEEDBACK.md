# CTP-013 private workflow feedback

An authenticated member can deliberately save their own private note about one workflow version. The required confirmation records private-save intent; it does not attest that the text is invented. Saving neither requests review nor shares or publishes the note. A separate exact-revision request and finite assigned moderator permission are required for review access; unrelated members and generic staff remain denied. Background and learning goal never change access. Workflow demonstrations remain file-backed and read-only; see [reviewed workflows](REVIEWED-WORKFLOWS.md) for their current editorial status.

The ordinary save/correction form retains CSRF, source/version, revision and explicit confirmation checks. Invalid or missing confirmation returns HTTP422; stale changes return HTTP409; uncertain writes require inspecting the saved note before another attempt. No AI provider or client system receives this note.

`workflow_feedback` keys a note by member, workflow ID and file version. Saves compare the current file version and expected note revision before a create or correction. A stale, unknown or retired version cannot receive a new write; retained historical notes remain version-labelled and withdrawable. The database foreign key cascades on local account deletion. The structured owner export includes retained notes within its existing record and byte limits; withdrawal and deletion remove them from subsequent exports. There is no search index, cache, public copy, external provider or new retained deletion event. Session expiry/revocation blocks access while the underlying note remains until withdrawal or deletion.

If the feature must be disabled, stop exposing the private routes and form link, preserve the table until an approved data-retention/deletion decision, and let members use the existing local account deletion path. Rollback must not silently drop retained private notes. No hosted storage, backup-erasure timing, rights license, qualified human review, publication or live community approval is inferred. Parent [#115](https://github.com/deepnative/deep-native-engine/issues/115) and content/rights gate [#97](https://github.com/deepnative/deep-native-engine/issues/97) remain open for attributed improvement proposals and reviewed publication.

## Expiry and uncertain outcomes

Issue [#463](https://github.com/deepnative/deep-native-engine/issues/463) bounds reads, saves and withdrawals through the database COMMIT reply and connection handback. The same transaction engine used by private practice permits at most 3 seconds for acquisition, 5 seconds per query and 10 seconds for the complete transaction; the remaining session authority can shorten every limit. Database clock observations are translated conservatively to a monotonic deadline. No late result is returned even when COMMIT itself succeeded.

An unconfirmed save or withdrawal returns HTTP503 and asks you to reopen the workflow and inspect your current note before taking another explicit action. It does not claim that nothing changed and never resubmits automatically. If the session expired, private access remains unavailable; this transaction path does not renew sessions; separately configured email access can recover an existing account. Test demonstrations renew only their invented fixture authority. A known invalid/stale write remains HTTP409; unavailable private reads return a content-free HTTP403.

Principal → workspace → feedback-row fences preserve the owner-export/withdrawal ordering from #369. Optimistic revisions prevent an old form from overwriting or withdrawing a newer note. Owned connections are discarded after use, including healthy transactions, to isolate deadline settings; this adds connection churn. No rollback is queued behind an unresolved query or attempted COMMIT. Committed data is retained despite an uncertain response.

Rollback preserves schema and private data. Restoring the previous reader reopens the demonstrated response-lifetime defect; pause the private feedback endpoints instead if compatible recovery cannot be maintained. See [scoped evidence](WORKFLOW-FEEDBACK-LIFETIME-EVIDENCE.md) and the issue for delivery state.
