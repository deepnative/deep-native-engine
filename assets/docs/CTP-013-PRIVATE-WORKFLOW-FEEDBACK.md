# CTP-013 private workflow feedback: synthetic local preview

Child [#311](https://github.com/deepnative/deep-native-engine/issues/311) adds one private, exact-version text note per member and fixed file-backed workflow draft. The three workflow files remain read-only, unreviewed demonstrations. Viewing or downloading them is public; saving feedback requires an active member session, same-origin CSRF token and explicit invented-text confirmation. Only the author can read, correct, export or withdraw a note. No moderator, editor, reviewer, operator or peer endpoint exposes it. Background and learning goal never change access.

`workflow_feedback` keys a note by member, workflow ID and file version. Saves compare the current file version and expected note revision before a create or correction. A stale, unknown or retired version cannot receive a new write; retained historical notes remain version-labelled and withdrawable. The database foreign key cascades on local account deletion. The structured owner export (currently `local-member-records-v21`) includes retained notes within its existing record and byte limits; withdrawal and deletion remove them from subsequent exports. There is no search index, cache, public copy, external provider or new retained deletion event. Session expiry/revocation blocks access while the underlying note remains until withdrawal or deletion.

If the feature must be disabled, stop exposing the private routes and form link, preserve the table until an approved data-retention/deletion decision, and let members use the existing local account deletion path. Rollback must not silently drop retained private notes. No hosted storage, backup-erasure timing, rights license, qualified human review, publication or live community approval is inferred. Parent [#115](https://github.com/deepnative/deep-native-engine/issues/115) and content/rights gate [#97](https://github.com/deepnative/deep-native-engine/issues/97) remain open for attributed improvement proposals and reviewed publication.

## Expiry and uncertain outcomes

Issue [#463](https://github.com/deepnative/deep-native-engine/issues/463) bounds reads, saves and withdrawals through the database COMMIT reply and connection handback. The same transaction engine used by private practice permits at most 3 seconds for acquisition, 5 seconds per query and 10 seconds for the complete transaction; the remaining session authority can shorten every limit. Database clock observations are translated conservatively to a monotonic deadline. No late result is returned even when COMMIT itself succeeded.

An unconfirmed save or withdrawal returns HTTP503 and asks you to reopen the workflow and inspect your current note before taking another explicit action. It does not claim that nothing changed and never resubmits automatically. If the session expired, private access remains unavailable; this preview does not introduce session renewal or account recovery. Test demonstrations renew only their invented fixture authority. A known invalid/stale write remains HTTP409; unavailable private reads return a content-free HTTP403.

Principal → workspace → feedback-row fences preserve the owner-export/withdrawal ordering from #369. Optimistic revisions prevent an old form from overwriting or withdrawing a newer note. Owned connections are discarded after use, including healthy transactions, to isolate deadline settings; this adds connection churn. No rollback is queued behind an unresolved query or attempted COMMIT. Committed data is retained despite an uncertain response.

Rollback preserves schema and private data. Restoring the previous reader reopens the demonstrated response-lifetime defect; pause the private feedback endpoints instead if compatible recovery cannot be maintained. See [scoped evidence](WORKFLOW-FEEDBACK-LIFETIME-EVIDENCE.md) and the issue for delivery state.
