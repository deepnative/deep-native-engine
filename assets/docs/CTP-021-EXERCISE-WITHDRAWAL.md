# Completed starter exercise text withdrawal (#363)

This local synthetic control lets an active member withdraw both saved text fields from one completed, version-pinned starter exercise. The exercise row remains as a text-free self-report: `completed_at`, lesson ID/version and `goal_at_start` stay unchanged. Prerequisite and activity history continue to mean self-reported completion, not qualified assessment. No other member's records change. The owner can withdraw a retained older version after changing direction or after the current source version changes. Unfinished drafts are outside this control.

Migration 043 adds `withdrawn_at`, makes `instruction` and `verification` nullable, and constrains each row to either two non-null active text fields with no withdrawal time, or two null fields with a withdrawal time and an existing completion time. Existing rows need no data rewrite. A completed row cannot be edited; a withdrawn row cannot be refilled by a stale form. Account deletion cascades the marker and all exercise metadata.

Withdrawal authenticates the current member token and locks the principal, nondeleting owned workspace and exact exercise row in that order. It rechecks wall-clock expiry before commit. New exercise forms pin the lesson ID and version; a missing or mismatched pin is rejected without echoing attempted text, so a form from an older source cannot silently create a new-version copy. Lesson rendering holds owner/workspace/exercise read locks while forming HTML; the structured owner export and authorized staff workspace read likewise hold exercise locks while forming their result. A read that started first may finish before withdrawal commits; a read formed after withdrawal commits must see null text or fail closed. Previously displayed or downloaded copies cannot be recalled. Failed known writes roll back; uncertain outcomes show a text-free recovery page and direct the owner to inspect the saved lesson. No database detail appears in the response.

`local-member-records-v9` adds `state` and `withdrawnAt` to each retained exercise record. A withdrawn row exports `instruction: null` and `verification: null`, while preserving the self-reported completion fields. Existing ordering and record/byte limits remain. Reverting to an older binary without marker-aware reads or writes could hide the withdrawal state or mishandle nullable text. For rollback, keep migration 043 and the redacted rows, disable the exercise save/lesson/workspace-read/export paths until a compatible binary is restored, and never repopulate text from a backup. The additive migration is not reversed in place.

This control does not establish hosted backup erasure, production retention, complete portability, legal acceptance, qualified review or release readiness. Parent #40 remains open for its wider criteria and owner/qualified decisions.
