# Bounded private evidence export in the local preview

CTP-021 child #236 introduced the owner-only JSON export in the private evidence manager. The current response is versioned `local-evidence-v2` and returns live continuation pages, each containing at most 20 currently owned evidence records and 4 MiB of raw clean source bytes. It includes each record's ID, original name, media type, safety state, private-review consent/revocation state and creation time. Only clean active source bytes are included, encoded as base64. Pending, rejected and infected records retain metadata but have `sourceBase64: null`; deleting records are excluded. No staff identity, storage key, download capability, raw session token or derivative bytes are included. The JSON is larger than the raw-byte limit because of base64 encoding.

Each page reauthorizes the member, then holds the principal, non-deleting workspace and selected evidence rows in one PostgreSQL transaction while source bytes are read. The exporter checks stored byte count and SHA-256 against every included clean source before returning that page; missing or corrupt storage makes the page unavailable. Revoked/expired/nonmember sessions are denied. The principal check uses PostgreSQL wall time, and a second wall-time check immediately before commit denies the assembled page if the session expired during lock acquisition or storage reads. `CURRENT_TIMESTAMP` alone is insufficient because it is frozen at transaction start. A failed rollback discards the database connection rather than returning a possibly locked transaction to the pool. A larger collection advances through bounded pages rather than rejecting the entire export. The server sends each JSON page as an attachment with `Cache-Control: no-store`. The global Host/session boundary still applies. A deletion or session revocation that starts first prevents stale export; either action that starts during a page waits for that page's transaction to finish. Private-review consent revocation does not remove the owner’s export right, but its changed state appears in later pages.

Continuation uses a signed, session-bound cursor with the exact PostgreSQL ordering timestamp and record ID. It expires 15 minutes after the first page and is checked again before each page commits. The next-page link is revealed only after the member actually downloads the preceding JSON response; a failed download clears that link. Pages are separate live reads, not a frozen snapshot. If records or consent change between pages, the member should start a new export. The authorization boundary ends at each page transaction's commit; it cannot recall an already delivered response.

This is a local-preview evidence export, not a complete member data portability response. It excludes assignments, milestones, career plans, private proposals, circle memberships, derivatives, AI/provider material, billing and hosted backups. The pending PLAN-002 retention/privacy decision and CTP-021 #40 remain open. F-BUILD-08-A is not counted as covered in the approved or provisional full-MVP register from this slice. No live services, production storage or external transfers are authorized.

Verification uses behavioral unit checks for identity, per-page record/byte limits, cursor rejection, unsafe-state exclusion, content integrity and storage/database failure; real PostgreSQL integration with separate owners, timestamp ties, safety states, consent revocation, deletion and controlled expiry/revocation orderings; and desktop/mobile browser journeys L59 and L92 for private page downloads, continuation, outsider exclusion, live changes and no-store headers. Child #365 first reproduced the expiry leak on unchanged main `9f9e307` with a paused real object read and independently observed PostgreSQL expiry before repair. The export does not promise hosted-copy erasure. The exact-commit gate, normal pre-push hook, PR CI and resulting-main CI are required before Done. Rollback is the commit revert; existing individual owner downloads remain available independently.
