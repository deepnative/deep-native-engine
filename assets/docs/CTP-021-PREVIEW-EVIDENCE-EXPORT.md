# Bounded private evidence export in the local preview

CTP-021 child #236 adds an owner-only JSON export link to the private evidence manager. The response is versioned `local-evidence-v1` and contains at most 20 currently owned evidence records. It includes each record's ID, original name, media type, safety state, private-review consent/revocation state and creation time. Only clean active source bytes are included, encoded as base64. Pending, rejected and infected records retain metadata but have `sourceBase64: null`; deleting records are excluded. No staff identity, storage key, download capability, raw session token or derivative bytes are included.

The current member principal and evidence rows are checked and held in one PostgreSQL transaction while source bytes are read. The exporter checks stored byte count and SHA-256 against every clean source before returning any response; missing or corrupt storage makes the whole request unavailable. Revoked/expired/nonmember sessions are denied. A request with more than 20 records or over 4 MiB of clean source bytes fails closed with a useful individual-download/delete path. The server sends an attachment with `Cache-Control: no-store`. The global Host/session boundary still applies. A deletion or session revocation that starts first prevents the stale export; either action that starts during the export waits for the transaction to finish. Private-review consent revocation does not remove the owner’s export right, but its changed state appears in later exports.

This is a local-preview evidence export, not a complete member data portability response. It excludes assignments, milestones, career plans, private proposals, circle memberships, derivatives, AI/provider material, billing and hosted backups. The pending PLAN-002 retention/privacy decision and CTP-021 #40 remain open. F-BUILD-08-A is not counted as covered in the approved or provisional full-MVP register from this slice. No live services, production storage or external transfers are authorized.

Verification uses behavioral unit checks for identity, record/byte limits, unsafe-state exclusion, content integrity and storage/database failure; real PostgreSQL integration with separate owners, safety states, consent revocation and deletion; and the existing L59 desktop/mobile browser journey for the public export route, pending/clean/deleted responses, outsider exclusion and no-store headers. The exact-commit gate, normal pre-push hook, PR CI and resulting-main CI are required before Done. Rollback is the commit revert; existing individual owner downloads remain available independently.
