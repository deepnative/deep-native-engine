# Deterministic local AI pause control

Issue [#343](https://github.com/deepnative/deep-native-engine/issues/343) adds an operational switch for the private **demo/test** simulation introduced by [#341](https://github.com/deepnative/deep-native-engine/issues/341). It does not turn on a live provider, create an AI allowance, approve consent text or settle a cost. Parent [#188](https://github.com/deepnative/deep-native-engine/issues/188) retains those separate decisions.

The one PostgreSQL control row records whether local simulation is paused. The migration seeds the existing local behavior as enabled only when the control table is first created; it does not overwrite a later administrator choice. A missing row, invalid state or database failure blocks queue and dispatch. Only an active `platform_admin` may change the row through `/operator/local-ai`; other staff and members cannot. The member page shows the current local availability and keeps permission withdrawal available while paused. Its display is informational: queue and dispatch read the database again.

Queue and both phases of dispatch lock the control before member principal, workspace, source, permission and job. The final dispatch transaction keeps the control lock through the bounded deterministic adapter and outcome commit. A pause that wins first blocks a new queue or invocation. A dispatch that wins first commits its already claimed attempt before pause returns. A pause between durable claim and invocation leaves that attempt held; resume does not reset it to pending or automatically retry it. Consent withdrawal, revision retirement and deletion remain authoritative after resume. Live/provider mode stays unavailable regardless of the switch.

To pause or resume a local test, use the platform-admin page and confirm the explicit requested state. Verify the page's resulting state before treating the change as effective. The switch affects no unrelated jobs or synthetic entitlement ledger category. Rollback to the earlier #341 binary is **not** a safe way to maintain a pause because that binary does not read the new row: stop local dispatch/processes before binary rollback, and resume only after reviewing the control path. Database migration reruns must not reset a saved choice. No production deployment is implied by this local procedure.

Verification is recorded on the child issue and PR: fail-first browser and real-PostgreSQL behavior, role and expiry denial, persisted-state restart, both lock orderings, claim-between-phases ambiguity, no automatic held retry, compiled-server desktop/mobile journey, exact-commit shared gate, unbypassed push hook, PR CI and resulting-main CI. The accepted full-MVP register remains separate from this local preview.
