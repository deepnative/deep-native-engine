# Local private-review intent

An active member may mark one owned, clean, explicitly consented invented evidence object for possible private review from `/evidence`. The checkbox states that no qualified reviewer is assigned and no response time is promised. The `POST /evidence/:id/queue` form is CSRF-protected and calls the existing `submitForReview` write, which checks current member ownership, quarantine, consent and uniqueness in PostgreSQL. A stale, duplicate or unauthorized request returns the same generic ineligible state and does not create another submission.

The page reads current owner-filtered metadata after a write. `queued` means a local submission record exists; it is not a booking, grant, human review, quality judgment or notification. Revoking private-review consent changes a queued submission to `withdrawn`, blocks another queue attempt and prevents current reviewer access, while preserving the owner's private download. Deletion removes the configured evidence and cascades its submission. No assignment attempt is promoted or copied into evidence storage, and #125's retention and consent decision remains open.

L60 runs the owner and unrelated-member browser flow on desktop/mobile Chromium. Unit route tests exercise missing acknowledgement, CSRF and stale/allowed responses; PostgreSQL integration covers owner, unrelated member, staff, duplicate and withdrawn states. The local `initial-learning-v28` gate remains separate from the 100-case full-MVP register. This synthetic preview has no live scanner, qualified staffing, formal assessment, hosted retention, funded review or commercial launch.

Queue insertion locks the eligible evidence row before writing the submission. Consent revocation updates that same row and then withdraws any queued submission in a second statement within one transaction. This ordering makes an overlapping queue finish before withdrawal, or rechecks consent after withdrawal and denies the queue. A failed withdrawal rolls back the consent change. A controlled PostgreSQL trigger/advisory-lock test reproduces the earlier `queued`-after-revocation state and proves the corrected ordering without a timing-only sleep; concurrent duplicates still create one record. Row locking does not activate reviewer access or change the separate current-consent check on reviewer downloads.

Rollback of the queue/revocation serialization fix must preserve existing `evidence_review_submissions` rows and consent revocations. Reverting the lock/transaction change would restore the concurrent stale-queue defect and should be paired with disabling the queue action until corrected; do not reactivate withdrawn consent or expose queue records to another principal.
