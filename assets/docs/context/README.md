## Board conventions

All new issues start open in Backlog; no agents are assigned to implement them. Stable IDs retain source traceability. Milestones identify delivery stages, labels identify phase, priority and work type, and each issue lists dependencies, observable acceptance criteria, evidence, non-goals and a definition of done. Phase epics collect stage gates; the master roadmap connects them. Dates from the original plan are relative estimates, not promised delivery dates.

`issues.json` is the prepared specification register; `github-issues.json` maps it to published GitHub issues. GitHub becomes the operating backlog after publication. Local files are a context archive and handoff, not a competing status system.
